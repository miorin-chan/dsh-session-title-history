# 会话标题历史开发说明

Host 通过 Connection 的认证通道按需读取一个会话。`sessionQuery.observeSession` 也能读取归档日志。
接口只返回 `session/title` 的序号、时间、标题、来源及继承标记；日志原样保留。
按事件顺序推导旧标题，之后按序号倒序显示。
文本相同的写入也保留，以反映来源变化和手动固定。

客户端向 `contextMenus` 注册原生会话菜单项，排在「复制会话 ID」上一项，并通过 `contextMenu.icon` 提供原生时钟图标。
标题历史与复制会话 ID 共用组首分隔线。
`0.2.2-rc.5` 的注册接口只允许贡献方设置自己的分隔线，因此样式在这两个原生菜单行相邻时隐藏复制项原来的分隔线。
弹窗由 `shell.overlay` 挂载，复用宿主提供的 `Modal`、`Button` 和 `Tooltip`。
历史列表只在标题实际变化时新增主行，连续同名写入收在该标题下，默认折叠。
标题后用原生 `Tag` 标出折叠的条数，点击整行标题展开或收起，悬停或聚焦时用 `Tooltip` 说明。
悬停、聚焦或点按「自动生成」可查看标题提供方及模型。
当前标题以及与它同名的过去标题不提供操作，因为再写入同名标题只会多出一条「文字未变」记录。
其余每组标题右侧有方形图标按钮，图标取原生的右上箭头字形，点击后走原生重命名接口把该标题重新设为当前标题。
客户端通过 `sessions.using` 临时持有会话，再调用 `SessionFace.rename`，与原生重命名弹窗同一条路径；
引用来源标签 `dsh-session-title-history` 通过声明合并登记到 `SessionReferenceSourceMap`。
是否显示按钮读取插槽全局钩子 `useSessionAccess(sessionId, 'session/rename')`，与原生「重命名」菜单项的判定一致。
设置期间按钮全部禁用，成功后重新读取历史，列表与状态行一起更新；失败时在弹窗内显示原因。
点击后焦点先落到滚动区域，因为被点击的按钮会随该标题变为当前标题而离开列表；
成功后焦点移到下一个更早的可操作标题，失败时回到被点的按钮。
触屏设备把按钮放大到 36 px，因为没有悬停说明可以解释图标。
颜色跟随 DSH 主题。停用时清理由插件注册的菜单、弹层与读取接口。
分叉只呈现实际继承的前缀。DSH 客户端的分叉命名也走原生重命名接口，日志将其记为 `user`。
界面按这个来源标注。未写入或已丢失的历史无法恢复。

## 构建与验证

```sh
npm ci
npm run build
npm run check
npm pack --dry-run
```

从工作区根目录运行 `node tools/new-dsh-plugin/cli.mjs --check plugins/dsh-session-title-history`。
升级 DSH 后重新核对会话日志字段、菜单入口、弹窗、分叉标记、独立开关、重命名接口与 `session/rename` 权限判定。
